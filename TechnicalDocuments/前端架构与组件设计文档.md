# 通用数据分析工具前端架构与组件设计文档

## 1. 架构概述

基于设计图，通用数据分析工具前端采用现代化的单页应用架构，旨在为用户提供直观、高效的数据分析体验。本架构遵循组件化、模块化的设计原则，确保代码的可维护性和可扩展性。

### 1.1 技术栈
- **框架**：React 18 + TypeScript
- **构建工具**：Vite
- **UI组件库**：Ant Design
- **状态管理**：React Context API + 自定义Hooks
- **路由**：React Router
- **数据可视化**：ECharts/D3.js
- **HTTP客户端**：Axios

## 2. 页面布局设计

根据提供的设计图，前端界面主要包含三种视图：数据分析视图、仪表盘视图和绘图视图。其中，设计图仅详细展示了数据分析界面的布局，仪表盘视图可自由实现，绘图视图暂时留空。

### 2.1 数据分析视图布局（根据设计图）

数据分析视图采用经典的三栏布局设计，包含顶部导航栏、左侧功能区和右侧操作区，中间为主要内容区域。

```

|                       （仪表盘 / 数据分析 / 绘图）                |
+---------------------------------------------------------------+

|    |              参数输入及控制面板          |       消息返回        |
|    |                                 |                         |
|    |                                 |                         |
|    |                                 |                         |
|    |                                 |                         |
|  功能|                                 |                         |
|  列  |                                 |                         |
|  表  |                                 |                         |
|    |                                 |                         |
|    |                                 |                         |
|    |                                 |                         |
|    +---------------------------------+                         |
|    |                                 |                         |
|    |            结果展示               |       清空/重置按钮     |
|    |                                 |                         |
```

### 2.2 各区域功能说明

1. **顶部导航栏**：显示应用名称和主要视图切换（仪表盘、数据分析、绘图）。
   - 包含应用标题："通用数据分析工具"
   - 提供视图切换按钮："仪表盘"、"数据分析"、"绘图"
   - 处理全局状态和用户信息展示

2. **左侧功能列表**：垂直排列数据处理的各个步骤，包含状态指示。
   - 导入
   - 预览
   - 清洗
   - 分析
   - 可视化
   - 报表
   - 每个步骤都有状态指示器（圆圈）

3. **中间参数输入及控制面板**：根据当前选中的功能步骤，显示对应的参数设置和操作按钮。
   - 动态加载与当前步骤相关的表单组件
   - 提供操作按钮（如"开始分析"、"生成图表"等）
   - 显示进度和状态信息

4. **中间结果展示区**：显示数据处理的结果、图表、报表等。
   - 动态加载结果展示组件
   - 支持表格、图表、文本等多种展示形式
   - 提供结果导出功能

5. **右侧消息返回区**：显示操作日志、错误信息和系统提示。
   - 实时显示操作反馈
   - 提供消息过滤和清空功能

6. **右侧清空/重置按钮**：提供全局操作控制。
   - 清空当前结果
   - 重置整个工作流程

### 2.3 仪表盘视图设计（自由实现）

仪表盘视图采用卡片式布局，用于概览数据分析项目和快速访问常用功能。

- **项目概览区域**：显示最近的分析项目、数据导入情况等统计信息
- **常用工具卡片**：提供快速启动数据导入、清洗、分析等常用功能的入口
- **数据可视化卡片**：展示关键指标和趋势图表
- **通知中心**：显示系统通知和提醒

### 2.4 绘图视图设计（暂时留空）

绘图视图目前暂未详细设计，将在后续版本中完善。

## 3. 组件设计

### 3.1 核心组件

#### 3.1.1 Header组件

负责顶部导航栏的渲染和全局状态管理。

**属性**：
- `activeView`: 当前激活的视图类型
- `onViewChange`: 视图切换回调函数

**功能**：
- 显示应用标题
- 渲染视图切换按钮（仪表盘、数据分析、绘图）
- 处理视图切换事件

#### 3.1.2 WorkflowSidebar组件

负责左侧功能列表的渲染和工作流状态管理。

**属性**：
- `steps`: 工作流步骤列表
- `activeStep`: 当前激活的步骤
- `stepStatuses`: 各步骤的状态信息
- `onStepChange`: 步骤切换回调函数

**功能**：
- 渲染工作流步骤列表
- 显示各步骤状态（未开始、进行中、已完成）
- 处理步骤切换事件
- 实现步骤间的逻辑流转

#### 3.1.3 MainContent组件

负责中间区域的内容渲染，根据当前选中的步骤动态加载对应组件。

**属性**：
- `activeStep`: 当前激活的步骤
- `sessionData`: 当前会话数据
- `onDataUpdate`: 数据更新回调函数

**功能**：
- 动态加载步骤对应的组件
- 传递数据和回调函数
- 处理结果展示

#### 3.1.4 MessagePanel组件

负责右侧消息返回区的渲染和消息管理。

**属性**：
- `messages`: 消息列表
- `onClearMessages`: 清空消息回调函数

**功能**：
- 显示操作日志和系统消息
- 支持消息过滤和清空
- 实现消息自动滚动

### 3.2 功能模块组件

#### 3.2.1 DataImport组件

负责数据导入功能，支持文件上传和数据库连接。

**功能**：
- 文件上传（支持CSV、JSON、XLSX格式）
- 数据库连接配置（支持SQLite、PostgreSQL等）
- 显示上传进度和状态
- 处理导入成功/失败逻辑

#### 3.2.2 DataPreview组件

负责导入数据的预览功能。

**功能**：
- 以表格形式展示导入的数据
- 显示数据统计信息（行数、列数、数据类型等）
- 支持数据筛选和排序
- 提供列选择功能

#### 3.2.3 DataCleaning组件

负责数据清洗功能。

**功能**：
- 提供标准、严格、宽松和自定义四种清洗模式
- 支持缺失值处理、异常值检测、重复值移除等操作
- 允许用户配置自定义清洗参数
- 显示清洗前后的数据对比

#### 3.2.4 DataAnalysis组件

负责数据分析功能。

**功能**：
- 提供多种分析模型选择（回归、分类、聚类等）
- 支持模型参数配置
- 显示分析结果和评估指标
- 支持特征重要性展示

#### 3.2.5 DataVisualization组件

负责数据分析视图中的数据可视化功能。

**功能**：
- 提供多种图表类型选择（柱状图、折线图、散点图、热力图等）
- 支持图表参数配置（标题、坐标轴、图例等）
- 实现交互式图表（缩放、拖拽、悬停显示详情）
- 提供图表导出功能

> 注意：专门的绘图视图功能暂未实现，将在后续版本中开发。

#### 3.2.6 ReportGeneration组件

负责报表生成功能。

**功能**：
- 支持多种报表格式选择（PDF、HTML、Excel等）
- 允许用户配置报表内容和样式
- 显示生成进度
- 提供报表下载功能

## 5. API接口对接

前端通过Axios与后端FastAPI服务进行通信，主要对接以下API端点：

### 5.1 会话管理API
- **创建会话**：POST /api/import/create-session
- **获取会话状态**：GET /api/import/session-status
- **重置会话步骤**：POST /api/import/reset-step
- **删除会话**：DELETE /api/import/delete-session

### 5.2 数据导入API
- **上传文件**：POST /api/import/upload-file
- **从数据库导入**：POST /api/import/import-from-database
- **从API导入**：POST /api/import/import-from-api

### 5.3 数据预览API
- **获取数据预览**：GET /api/preview/get-preview
- **获取数据统计**：GET /api/preview/get-stats

### 5.4 数据清洗API
- **设置清洗参数**：POST /api/cleaning/set-params
- **执行数据清洗**：POST /api/cleaning/clean-data
- **获取清洗结果**：GET /api/cleaning/get-result

### 5.5 数据分析API
- **设置分析参数**：POST /api/analysis/set-params
- **执行数据分析**：POST /api/analysis/analyze
- **获取分析结果**：GET /api/analysis/get-result
- **获取评估指标**：GET /api/analysis/get-metrics

### 5.6 数据可视化API
- **设置可视化参数**：POST /api/visualization/set-params
- **生成图表**：POST /api/visualization/generate-chart
- **获取图表数据**：GET /api/visualization/get-chart-data

### 5.7 报表生成API
- **设置报表参数**：POST /api/reporting/set-params
- **生成报表**：POST /api/reporting/generate-report
- **下载报表**：GET /api/reporting/download-report

## 6. 工作流设计

### 6.1 基本工作流

用户按照以下步骤完成数据分析任务：

1. **创建会话**：系统自动创建新的会话或使用现有会话
2. **导入数据**：通过文件上传、数据库连接或API调用导入数据
3. **预览数据**：查看导入数据的基本信息和内容
4. **清洗数据**：根据需要对数据进行清洗和预处理
5. **分析数据**：选择合适的模型和参数进行数据分析
6. **可视化结果**：生成图表直观展示分析结果
7. **生成报表**：将整个分析过程和结果导出为报表

### 6.2 步骤间的逻辑关系

- 各步骤按顺序执行，前一步骤完成后才能进行下一步骤
- 可以回溯到之前的步骤进行修改，但会导致后续步骤的数据失效
- 每个步骤完成后会自动锁定，防止意外修改
- 提供全局重置功能，清空所有步骤的数据和状态

## 7. 响应式设计

前端界面支持响应式设计，适配不同屏幕尺寸：

- **桌面端（≥1200px）**：完整三栏布局
- **平板端（768px-1199px）**：右侧消息面板折叠，通过按钮切换显示
- **移动端（<768px）**：所有侧边栏折叠，通过顶部导航切换功能

## 8. 安全性考虑

- **API请求安全**：所有API请求都包含会话ID，防止未授权访问
- **数据传输安全**：使用HTTPS协议进行数据传输（生产环境）
- **错误处理**：完善的错误处理机制，防止程序崩溃
- **用户输入验证**：在前端对用户输入进行初步验证，减少后端压力

## 9. 部署和构建

### 9.1 开发环境
- 使用Vite提供的开发服务器
- 配置代理转发到后端API

### 9.2 生产环境
- 使用Vite构建优化的静态资源
- 部署到Nginx或其他Web服务器
- 配置Gzip压缩和缓存策略

### 9.3 清理任务说明
后端API包含自动清理任务（cleanup_task.py），默认每5分钟执行一次，负责清理：
- 过期的会话数据
- APIOutput目录中的临时文件
- 临时存储目录（Src/DataAnalyzer/TempStorage）中的导入、清洗、分析和可视化数据

清理任务以守护线程方式运行，确保系统资源得到有效管理。
