# ManualWorkflow 核心工作流接口文档

## 概述

`ManualWorkflow` 是整个数据分析工具的核心工作流（位于 `backend/Services/workflows/manual_workflow.py`），提供统一的接口来执行完整的数据分析流程。它封装了数据导入、预览、清洗、分析、可视化及报告生成等步骤，通过 `WorkflowContext` 维护各步骤产物，并以 `StepStateMachine` 状态机保证流程有序执行。

步骤顺序：`import → preview → cleaning → analysis → visualization → report`

## 类：ManualWorkflow

### 构造函数

```python
from backend.Services import ManualWorkflow

workflow = ManualWorkflow()
```

初始化手动工作流，注册各步骤部件（导入/预览/清洗/分析/可视化/报表）。

### 方法

#### execute_step()

执行指定步骤并返回产物（Artifact）。

```python
execute_step(
    context: WorkflowContext,
    step: StepName,
    params: Optional[Dict[str, Any]] = None
) -> Artifact
```

**执行逻辑：**
1. 校验锁状态（已锁定步骤抛 `StepLocked`）
2. 校验前置步骤是否完成（不满足抛 `WorkflowOrderError`）
3. 从部件注册表取部件执行
4. 产物写入 `context.artifacts` 并落 temp_storage
5. 推进状态机（标记完成；import/cleaning/analysis 完成后自动锁定）

**前置条件：**
- `PREVIEW` / `CLEANING`：需先完成 `IMPORT`
- `ANALYSIS`：需先完成 `CLEANING` 或 `IMPORT`
- `VISUALIZATION` / `REPORT`：需先完成 `ANALYSIS`

**各步骤参数字典：**

| 步骤 | 主要参数 |
|---|---|
| IMPORT | `resource_path`, `resource_type`, `is_database`, `db_connection_string`, `query`, `chunksize` |
| PREVIEW | `rows`（预览行数） |
| CLEANING | `select_mode`, `params_list`, `is_freedom_params`, `target_col` |
| ANALYSIS | `model_type` 或 `model`, `target_col`, `feature_cols`, `metrics_list` 等 DataAnalyzer 全参数 |
| VISUALIZATION | `param_dict`（可视化参数，缺省用分析结果默认参数） |
| REPORT | `report_type` |

**异常：**
- `StepLocked`: 步骤已锁定时抛出
- `WorkflowOrderError`: 前置步骤未完成时抛出
- `ImportError_` / 其它领域异常：步骤执行失败时抛出

## 类：WorkflowContext

工作流上下文（位于 `backend/Services/workflows/context.py`），持有会话的步骤状态机、产物与临时存储。

### 构造函数

```python
from backend.Services.workflows.context import WorkflowContext

context = WorkflowContext(session_id: str)
```

### 属性

- `session_id` (str): 会话ID
- `steps` (StepStateMachine): 步骤状态机（锁状态唯一来源）
- `artifacts` (Dict[StepName, Artifact]): 各步骤产物

### 方法

#### get_artifact() / set_artifact() / clear_artifact()

产物读写。`set_artifact` 会同步落 temp_storage。

#### reset_step()

级联重置某步骤及其后续步骤。

```python
reset_step(step: StepName) -> List[StepName]
```

此操作会：
1. 解锁当前步骤及后续所有步骤
2. 移除当前步骤及后续步骤的完成状态
3. 清除相关步骤的 Artifact 与 temp_storage 数据

#### reset_all()

重置会话全部数据。

#### get_temp_storage()

获取临时存储管理器。

## 类：StepStateMachine

步骤状态机，提供 `complete` / `lock` / `unlock` / `is_locked` / `is_completed` / `reset_from` / `status` 方法。`status()` 返回前端契约格式：

```python
{"completed_steps": [...], "locked_steps": [...]}
```

## 使用示例

### 基本使用流程

```python
from backend.Services import ManualWorkflow
from backend.Services.workflows.context import WorkflowContext
from backend.shared.types import StepName

workflow = ManualWorkflow()
context = WorkflowContext("my_session")

# 1. 数据导入（完成后自动锁定）
workflow.execute_step(context, StepName.IMPORT, {
    "resource_path": "Data/iris.csv", "resource_type": "csv"
})

# 2. 数据清洗（完成后自动锁定）
workflow.execute_step(context, StepName.CLEANING, {
    "select_mode": "standard", "params_list": [], "target_col": "target"
})

# 3. 数据分析（完成后自动锁定）
artifact = workflow.execute_step(context, StepName.ANALYSIS, {
    "model_type": "logisticregression", "target_col": "target"
})

# 4. 数据可视化
workflow.execute_step(context, StepName.VISUALIZATION, {})

# 5. 生成报告
workflow.execute_step(context, StepName.REPORT, {})

# 获取步骤状态
status = context.steps.status()
print(f"已完成步骤: {status['completed_steps']}")
print(f"已锁定步骤: {status['locked_steps']}")

# 重置分析步骤及其后续步骤（可视化、报告）
context.reset_step(StepName.ANALYSIS)
```

### 数据库导入示例

```python
workflow.execute_step(context, StepName.IMPORT, {
    "resource_path": "table_name",
    "resource_type": "sqlite",
    "is_database": True,
    "db_connection_string": "sqlite:///database.db",
    "query": "SELECT * FROM table_name"
})
```

### 交互式可视化示例

```python
# 分析完成后，通过可视化步骤的 param_dict 启用交互式图表
workflow.execute_step(context, StepName.VISUALIZATION, {
    "param_dict": {"interactive": True}
})
```

### 步骤管理示例

```python
# 查看当前步骤状态
status = context.steps.status()
print(f"已完成步骤: {status['completed_steps']}")
print(f"已锁定步骤: {status['locked_steps']}")

# 重置清洗步骤及其后续步骤（分析、可视化、报告）
context.reset_step(StepName.CLEANING)

# 确认步骤状态已重置
status = context.steps.status()
print(f"重置后已完成步骤: {status['completed_steps']}")
print(f"重置后已锁定步骤: {status['locked_steps']}")
```

### 字符串目标列自动编码

清洗部件支持自动处理字符串类型的目标列。当在 CLEANING 步骤参数中指定 `target_col` 时，如果该列包含字符串类别（如 "benign" 和 "malignant"），系统会自动使用标签编码将其转换为数值形式（如 0 和 1），以便机器学习模型能够正确处理。

这对于处理真实世界的数据集非常有用，因为许多数据集的目标列都是以字符串形式表示的类别。
